# 扩展规划：全音域钢琴音源（打破音符盒限制）

> 目标：在保留"纯原版红石机械"核心体验的前提下，实现 MIDI 的**全音域（88 键）、力度（velocity→音量）、真实钢琴音色**复现。
> 状态：**已实施（v0.1.2）——方案从"新增扬声器方块"改为用户定稿的"Mixin 拦截原版音符盒 + 音高通道"**（保留原版音符盒外观与机械，选择性接管发声；详见 实现说明.md 第七轮）。音源定稿 Salamander（CC-BY 3.0）。

---

## 1. 现状与硬限制（全部有反编译依据）

| 能力 | 音符盒现状 | MIDI 需求 | 差距 |
|---|---|---|---|
| 音域 | **2 个八度**（NOTE 0–24 = MIDI 54–78，F#3–F#5），`getPitchFromNote = 2^((n-12)/12)` | 88 键（A0–C8，MIDI 21–108） | 范围外只能折八度（当前"最近可奏八度"策略），低音贝斯被抬、超高音被压 |
| 音色 | `NoteBlockInstrument` 是**写死的枚举**，20 种可调音乐器（26.1.2 含吉他/铜号四态），模组无法注册新乐器 | 128 种 GM 音色 | 只能近似映射 |
| 力度 | 固定音量 3.0，无 velocity | velocity 0–127 | 强弱全无 |
| 时值 | 固定衰减采样 | 音长任意 | 钢琴曲影响较小（自然衰减），弦乐/管乐影响大 |

**结论**：音符盒路线的"准确复现"上限就是上面四条。要突破，必须让"发声体"脱离音符盒。

## 2. 技术路线对比

| 路线 | 思路 | 音域/力度/音色 | 纯红石体验 | 结论 |
|---|---|---|---|---|
| A. 资源包替换采样 | 替换 `note_block/harp.ogg` 等 | ❌ 音域仍是 25 半音；❌ 力度 | ✅ | 只改善音色，不解决根本 |
| B. Mixin 音符盒发声 | 拦截 `NoteBlock.triggerEvent` 换自定义声音 | ❌ 音域仍受 NOTE 属性限制（方块里已丢失原始键位） | ✅ | 不解决音域，弃 |
| **C. 自定义"共鸣扬声器"方块 + BE + 自带音源素材（选定）** | 新方块，行为完全模仿音符盒（邻块变化→上升沿→发声），但 BE 里存**任意音高（float 无界）+ 力度（音量）+ 音色采样**，播放 `playSeededSound` 自定义 SoundEvent | ✅ 全 88 键（pitch=2^((key-root)/12) 无界）✅ 力度→音量 ✅ 真实钢琴采样 | ✅ **机械不变**：中继器链/波前/枝路全部照旧，扬声器像音符盒一样被红石物理触发；建筑仍是自运转的红石机器 | **选定** |
| D. 纯服务端调度播放（无方块） | BE 按 tick 直接 playSound | ✅ | ❌ 声音与红石建筑脱钩，"红石音乐"名存实亡 | 作为 C 的附加层可选，不单独用 |

**C 的核心洞察**：音符盒的限制在**枚举和属性**，不在"红石触发"本身。我们自己写的方块可以拥有同样的红石触发行为，却携带任意 BE 数据。

## 3. 选定方案详细设计（路线 C）

### 3.1 新方块与 BlockEntity
- 方块：`resonant_speaker`（共鸣扬声器），`BaseEntityBlock`，属性 `POWERED`（点亮视觉）。
- BE 数据（NBT）：`sample`（SoundEvent 注册名/采样索引）、`pitch`（float，无界）、`volume`（float）。
- 触发逻辑（照抄 NoteBlock 语义）：`neighborChanged` → `hasNeighborSignal(pos)` 上升沿 → `level.playSeededSound(null, pos, soundEvent, SoundSource.RECORDS, volume, pitch, seed)` + 置 POWERED；信号消失回落。**无 ticker，纯事件驱动**。
- 铺设布局与现有链完全一致：侧枝中继器 → 扬声器；下方统一铺轨道基座（扬声器不需要"音色底座"，基座种类减少，更简洁）。

### 3.2 音源素材（调研结论）
- **首选：Salamander Grand Piano V3+**（Yamaha C5 实录，[FreePats 官方分发](https://freepats.zenvoid.org)，CC-BY 3.0，可商用需署名——在 README/mods.toml 致谢即可）。音质公认优秀、"优美"诉求直接满足。
- **备选：VSCO 2 CE**（[Versilian Studios](https://versilian-studios.com)，**CC0 公有领域**，3GB 全管弦乐）——许可最干净，且为**阶段 2 多音色**（弦乐/铜管/贝斯/打击）一步到位。钢琴音色质量略逊 Salamander。
- UIowa 样本库：许可对模组重分发有限制，不用。
- **处理管线**：SFZ/WAV → 裁剪静音尾 → 归一化 → 单声道 22050Hz OGG（每采样 150–300KB）→ **每 3 半音取一个采样**（88 键 ≈ 30 个采样，pitch ±1.5 半音内，失真不可闻）→ 体积约 6–9MB，可接受。力度层：取 ff 层（响亮层）单层，力度用音量参数模拟。
- 注册：每采样一个 SoundEvent（DeferredRegister + sounds.json，约 30 个）。

### 3.3 数据模型与编排变更
- `ArrangedNote` 增加：`midiKey`（0–127，真实键位）与 `sampleIndex`；**扬声器模式下不做八度折叠**（全音域），`pitch = 2^((midiKey - sampleRootMidi)/12)` 在编排期烘焙进 BE。
- 音符盒模式维持现状（折叠照旧）——两种模式共存，同一编排管线，只是发声体不同。
- 序列化版本号 +1，旧编排在扬声器模式下按折叠音高回退（或要求重导入）。

### 3.4 模式选择
- UI"应用"前增加**音源模式**选择：`音符盒（原版音色，红石完全体）` / `共鸣扬声器（全音域钢琴）`。
- 两种模式的红石链/几何/清空逻辑 100% 共用，差异仅在"音符位置放音符盒还是扬声器"。

### 3.5 阶段划分
- **P1（本规划范围）**：扬声器方块 + 钢琴全音域 + 力度音量 + UI 模式选择 + Salamander 素材管线。
- **P2**：VSCO CE 多音色家族映射（弦乐/铜管/贝斯/打击各一组采样，GM 音色→家族→采样）。
- **P3**：立体声采样、尾音混响（长尾采样版）、每八度多力度层切换。

## 4. 风险与体积
- 模组体积 +6–9MB（OGG 单声道）——主流模组正常水平。
- BE 数量 ≈ 音符数（数千个），无 ticker，纯 NBT 存储，性能无虞。
- 扬声器被红石触发的时机与音符盒逐刻一致（同一 `neighborChanged` 语义），**播放与波前天然同步，无需额外调度**。
- 许可：Salamander 需在资源与 README 署名（CC-BY 3.0）；若想零负担，P1 直接用 VSCO CE 钢琴（CC0）。
